# 06 — Growth & Retention

## Growth principle

CAREL should not optimize for traffic before it proves execution value.

The strongest growth loop is likely product-led:

```text
User completes useful goal
↓
returns for another action
↓
uses more capabilities
↓
CAREL gains more context
↓
Agent becomes more useful
↓
user relies on CAREL more often
```

## Activation

Recommended activation event:

**A wallet completes its first reviewed CAREL execution.**

Secondary activation signals:

- user opens Portfolio after execution;
- user uses a second action type;
- user uses Agent goal input again.

## Retention

Potential retention drivers:

### Portfolio continuity

Users return because CAREL remembers or reconstructs positions they need to manage.

### More capabilities

A user who starts with Swap may later use:

```text
Bridge
Borrow
Lend
Stake
Privacy
```

### Monitoring

Future monitoring can create natural return frequency.

### Cross-chain workflows

Users return when CAREL becomes the interface for moving and using assets across ecosystems.

# Referral mechanics

Referral systems should only be added after users already value the product.

Bad sequence:

```text
weak product
→ points/referrals
→ temporary users
```

Better sequence:

```text
useful product
→ repeat usage
→ referral incentive
→ qualified users
```

## CAREL Points

Points can support:

- early-user recognition;
- campaign participation;
- protocol-specific quests;
- product experimentation.

But Points should not become the core reason users execute risky financial actions.

Avoid incentives that encourage users to take unnecessary leverage, bridge unnecessarily, or generate meaningless volume.

## Retention metrics

Track:

- 7-day returning wallets;
- 30-day returning wallets;
- executions per retained wallet;
- distinct capability types per wallet;
- Portfolio revisit rate;
- percentage of users who use Agent input repeatedly.

## Quality over vanity

Avoid treating these as primary evidence of product value:

- social followers;
- page views;
- Discord member count;
- raw wallet connects;
- points issued.

More meaningful signals:

```text
successful goal
repeat goal
second capability
managed position
recovered failed workflow
```
