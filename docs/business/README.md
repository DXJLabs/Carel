# CAREL Business Documentation

This directory explains CAREL as a business: how the product may create value, how it can reach users, where monetization may come from, which partnerships matter, and which assumptions still require validation.

Product design is documented separately in `docs/product/`.

Technical implementation is documented separately in `docs/technical/`.

## Business thesis

CAREL can create value by becoming the coordination layer between user intent and fragmented on-chain financial infrastructure.

Protocols provide financial primitives.

CAREL can provide:

```text
discovery
+
coordination
+
execution
+
privacy-aware routing
+
portfolio continuity
```

The business opportunity depends on whether users repeatedly rely on CAREL for execution rather than treating it as a one-time demo.

## Important distinction

Business documents contain hypotheses and strategy.

They should not be presented as proven traction, revenue, market share, or product-market fit unless supported by actual evidence.

CAREL should avoid inventing:

- users;
- volume;
- revenue;
- conversion;
- partnerships;
- market-size numbers;
- protocol endorsements.

Verified traction should be added only when it exists.
