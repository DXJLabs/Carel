# 04 — Go-To-Market Strategy

## GTM objective

The early GTM goal is not maximum reach.

It is to find users who experience the coordination problem strongly enough to become repeat users.

## Initial audience

Potential early users:

- Starknet DeFi power users;
- users already using several protocols;
- privacy-aware Starknet users;
- cross-chain users;
- crypto builders comfortable testing new execution products.

These segments should be validated through customer discovery.

## Initial wedge

A strong early message should be concrete.

Examples to test:

### Option A

**One Agent for Starknet DeFi execution.**

### Option B

**Public and private DeFi actions from one reviewed workflow.**

### Option C

**Tell CAREL what you want to do. Review the plan. Approve the transaction.**

The product should test messaging instead of assuming one positioning will work.

## Acquisition channels

## 1. Ecosystem communities

Relevant channels may include:

- protocol communities;
- Starknet developer/user communities;
- privacy communities;
- bridge and Bitcoin-on-Starknet communities.

Approach:

Demonstrate real workflows rather than posting generic product promotion.

---

## 2. Protocol partnerships

A protocol integration can create:

- technical credibility;
- co-marketing;
- user distribution;
- integration feedback.

Best partnership message:

> CAREL makes your protocol available as a capability inside goal-based execution.

---

## 3. Developer / builder audience

Technical documentation can attract:

- contributors;
- protocol teams;
- grant reviewers;
- ecosystem builders.

Content ideas:

- Agent architecture;
- privacy execution lifecycle;
- provider-neutral adapter design;
- cross-chain order recovery;
- Vesu vToken integration.

---

## 4. Product demos

Short demos should show one complete goal.

Example:

```text
User types goal
→ CAREL routes it
→ review
→ wallet
→ position/activity update
```

Avoid demos that only show interface animation.

---

## 5. Grants and accelerators

CAREL has characteristics relevant to ecosystem programs:

- protocol integrations;
- privacy;
- Agent infrastructure;
- cross-chain execution;
- open technical architecture;
- potential ecosystem distribution.

Grant applications should connect requested funding to measurable milestones.

# Early GTM loop

```text
Find targeted users
↓
Observe real workflow
↓
Show CAREL equivalent
↓
Get them to execute
↓
Measure where they stop
↓
Improve
↓
Invite them back
```

## Activation

Possible activation event:

**First successfully completed reviewed CAREL goal.**

Do not define activation as:

```text
wallet connected
```

Connecting a wallet does not prove product value.

## Retention hypothesis

Users return when CAREL becomes useful for:

- more than one financial primitive;
- managing existing positions;
- recurring portfolio actions;
- cross-chain workflow coordination;
- monitoring.

## Community strategy

Avoid creating a community based only on token speculation.

Build around:

- product usage;
- workflows;
- technical education;
- user feedback;
- partner integrations.

## GTM milestones

### Milestone 1

First external users complete live goals.

### Milestone 2

Same wallets return and execute again.

### Milestone 3

Users use more than one CAREL capability.

### Milestone 4

Users begin starting from Agent goals instead of manual navigation.

### Milestone 5

A protocol or ecosystem partner actively distributes CAREL.

These are more meaningful than raw social follower counts.
