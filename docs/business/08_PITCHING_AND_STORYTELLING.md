# 08 — Pitching & Storytelling

## Core story

A CAREL pitch should begin with the user's problem, not with a list of protocols.

Weak opening:

> CAREL integrates AVNU, Garden, Endur, Vesu, and STRK20.

Stronger opening:

> A simple on-chain financial goal can force a user to coordinate several protocols, networks, wallet prompts, and privacy states manually. CAREL turns that goal into a reviewed execution path.

## One-line pitch

**CAREL is an agentic on-chain execution interface that turns financial goals into reviewed public or private DeFi actions across supported protocols and ecosystems.**

## Short pitch

> DeFi has powerful infrastructure, but users still have to manually coordinate protocols, networks, routes, and transaction states. CAREL sits above that fragmentation. A user states a financial goal, the CAREL Agent translates it into a structured execution path, verifies supported providers and constraints, and lets the user review and approve the transaction in their wallet. CAREL already integrates Swap, Bridge, Staking, Borrow, Lend, and privacy-aware execution, while keeping the Agent separate from signing authority.

## Pitch structure

### 1. Problem

Show one realistic multi-step workflow.

```text
Bridge
→ wait
→ Swap
→ Shield
→ Lend
```

Ask:

Why should a user manually coordinate every transition?

### 2. Insight

Protocols solve primitives.

Nobody necessarily owns the user's complete goal.

### 3. Solution

CAREL owns the coordination layer.

```text
Goal
→ Agent
→ reviewed route
→ wallet
```

### 4. Demo

Show a complete goal, not a feature tour.

### 5. Why now

Frame carefully without unsupported market statistics.

Potential qualitative drivers:

- more chains;
- more protocols;
- better wallet standards;
- growing Agent interfaces;
- improving privacy infrastructure;
- increasing demand for abstraction.

### 6. Differentiation

Do not say only:

> We use AI.

Say:

```text
provider-neutral intent
privacy-aware lifecycle
deterministic execution validation
multi-protocol coordination
wallet-controlled authorization
```

### 7. Traction

Use only real evidence.

For the current stage, examples may include:

- production deployment;
- working protocol integrations;
- test coverage;
- Mainnet/Testnet execution architecture.

Add user or revenue metrics only after they exist.

### 8. Business

Present monetization hypotheses and explain how they preserve route neutrality.

### 9. Vision

End with:

```text
Today:
reviewed DeFi execution

Next:
multi-step coordination

Long term:
cross-ecosystem financial Agent
```

# Demo storytelling

Avoid:

```text
Here is the Home page.
Here is Portfolio.
Here is Settings.
```

Prefer:

```text
I want to borrow USDC and keep the proceeds private.
↓
CAREL understands Borrow + Shield.
↓
It prepares the public Vesu position.
↓
After confirmation, it shields the exact proceeds.
↓
The debt stays public; the resulting asset becomes private.
```

One workflow communicates more product value than ten screens.

# Pitch language rules

Use:

- "supports";
- "integrates";
- "currently";
- "reviewed";
- "goal-driven";
- "provider-neutral";
- "wallet-approved".

Avoid unless proven:

- "best";
- "fully autonomous";
- "zero risk";
- "completely private";
- "official partner";
- "market leader";
- "guaranteed yield".

Precision builds credibility.
