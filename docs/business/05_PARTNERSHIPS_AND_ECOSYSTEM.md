# 05 — Partnerships & Ecosystem Strategy

## Why partnerships matter

CAREL is intentionally provider-neutral.

That means partnerships are not optional extras; protocol relationships can be a core part of distribution and product depth.

## Partner categories

## Protocol partners

Examples of relevant capability categories:

```text
Swap
Bridge
Staking
Lending
Privacy
```

Value CAREL can offer:

- qualified execution flow;
- new UX surface for the protocol;
- multi-step composition;
- technical integration feedback;
- access to users who begin from goals rather than protocol names.

Value protocol can offer CAREL:

- stable APIs/contracts;
- technical support;
- co-marketing;
- integration grants;
- liquidity / route information;
- ecosystem credibility.

## Wallet partners

Wallets own the authorization boundary.

Potential collaboration:

- smoother capability detection;
- session-key research;
- safer multi-step approval UX;
- embedded CAREL Agent surfaces;
- deep links / execution handoff.

CAREL should not try to replace the wallet security boundary.

## Ecosystem / foundation partners

Ecosystem organizations may support:

- grants;
- developer resources;
- user distribution;
- events;
- technical introductions.

CAREL should position itself as infrastructure that makes ecosystem protocols easier to use together.

## Infrastructure partners

Potential categories:

- RPC;
- indexing;
- analytics;
- simulation;
- transaction monitoring;
- price/risk data.

These become more important as the Agent moves toward monitoring and multi-step strategy.

# Partnership principles

## Provider neutrality

A commercial partner should not automatically become the Agent's preferred route.

## Technical verification

Partnership status should never replace runtime safety checks.

## Clear disclosure

If CAREL receives financial incentives from a provider, this should not be hidden where it could affect user trust.

## No fake partnership language

Do not describe an integration as:

```text
"official partnership"
```

unless both parties have actually agreed to that relationship.

Technical integration, grant support, and commercial partnership are different things.

# Integration maturity model

### Level 1 — technical integration

CAREL can call and validate the provider.

### Level 2 — tested integration

Main flows are tested and monitored.

### Level 3 — partner-aware integration

Protocol team knows the integration and provides technical communication/support.

### Level 4 — distribution partnership

Both parties actively distribute the integration.

### Level 5 — strategic partnership

Shared roadmap, commercial terms, or embedded infrastructure.

This vocabulary helps CAREL avoid overstating relationships.
