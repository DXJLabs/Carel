# 07 — Grant & Investor Narrative

## Purpose

The same product should be described differently depending on the audience.

A grant reviewer and an investor do not ask exactly the same question.

# Grant narrative

A grant application should emphasize:

- ecosystem value;
- technical innovation;
- public infrastructure;
- integration depth;
- measurable milestones;
- how funding accelerates development.

## Example grant framing

### Problem

DeFi infrastructure is fragmented across protocol-specific interfaces, and privacy-aware multi-step execution remains difficult for users to coordinate.

### Solution

CAREL provides a goal-driven Agent layer that translates user intent into reviewed execution across supported DeFi and privacy infrastructure.

### Why the ecosystem benefits

CAREL can increase usability of existing protocols rather than requiring users to learn each protocol independently.

### Existing technical progress

Use verified facts only, such as:

- working Agent routing;
- protocol integrations;
- Mainnet/Testnet support;
- privacy execution;
- test coverage;
- production deployment.

### Milestones

Good grant milestones are measurable.

Example:

```text
Milestone 1:
Complete portfolio management for supported Vesu lending states.

Milestone 2:
Ship persistent multi-step Agent workflows.

Milestone 3:
Add another ecosystem through the generic adapter architecture.

Milestone 4:
Run external user validation and publish measured funnel results.
```

Do not use vague milestones such as:

> Grow the ecosystem.

# Investor narrative

An investor is more likely to care about:

```text
market pain
product wedge
retention
distribution
business model
moat
team velocity
scalability
```

## Investor story

### Problem

On-chain financial infrastructure is fragmented, forcing users to manually coordinate protocols, networks, and execution states.

### Product

CAREL turns financial goals into reviewed execution paths.

### Wedge

Privacy-aware DeFi execution and protocol coordination.

### Expansion

```text
Starknet execution
→ multi-protocol coordination
→ cross-ecosystem execution
→ portfolio monitoring
→ strategy Agent
→ infrastructure/API
```

### Potential moat

- execution graph;
- deep protocol adapters;
- user trust;
- portfolio context;
- workflow reliability;
- partner distribution.

### Business model

Present as hypotheses until validated:

- execution fees;
- subscription;
- protocol distribution;
- B2B Agent/execution API.

# What not to claim

Unless evidence exists, do not claim:

- product-market fit;
- revenue;
- active users;
- partnerships;
- transaction volume;
- market leadership;
- proprietary AI advantage;
- audited CAREL contracts if CAREL has not undergone such an audit.

# Evidence hierarchy

Strongest:

```text
on-chain executions
repeat users
revenue
signed partnerships
measured retention
```

Then:

```text
working product
tests
protocol integrations
production deployment
user interviews
```

Weakest:

```text
social engagement
idea enthusiasm
internal assumptions
```

Pitch from the strongest evidence available.
